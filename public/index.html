Auto reconciliation

Enter a database name and it discovers file-reference columns from the schema itself (information_schema) instead of typing table/column mappings by hand. Best-effort: review the discovered columns in the downloaded report before trusting it fully. Every TEXT/JSON column is also scanned for embedded Object Storage URLs (e.g. CKEditor/CKFinder uploads referenced only inside rich content) — anything found there is moved out of Orphan into Protected, so Orphan stays a safer basis for anything you plan to delete outside this tool.




DO cleanup candidates

Same auto-discovery as above, plus a scan of every TEXT/LONGTEXT column for Object Storage URLs embedded inline (e.g. CKEditor/CKFinder uploads referenced only inside HTML content). Produces an .xlsx listing which orphaned objects are safe cleanup candidates vs. which are protected because they're still referenced from inside rich-text content. Read-only — nothing is deleted.




Reconciliation

Match Object Storage against hand-typed MySQL table/column file references. Database is optional — when given, every TEXT/JSON column in it is also scanned for embedded Object Storage URLs, so Orphan doesn't wrongly include a file still referenced only inside rich-text/CKEditor content.

Copy files to another provider

Upload a reconciliation report you already downloaded — this reads its "Matched" sheet back in (files already confirmed to exist in both the database and storage) and copies every one of them to another provider (e.g. DigitalOcean -> Wasabi, ahead of a migration), no review list in between. Nothing is deleted from the source here — update the app's own database references to the new provider separately once you've confirmed the copy worked. Safe to re-run with the same (or an overlapping) report: anything already present at the destination is skipped instead of re-copied, unless "overwrite" below is checked. The destination bucket is created automatically if it doesn't exist yet, and copied files default to publicly readable (a plain object copy doesn't carry the source's ACL over, so without this a file that used to be public silently becomes private and every link to it breaks). Produces a downloadable .xlsx report with every file's new destination link.





Update database URLs after migration

Upload the completed storage migration report. Only Copied/Skipped rows with Table, Column, and Row ID are eligible. Each database value must still exactly match Source Path before it is changed to Destination URL; changed rows are reported as conflicts and left untouched. The run is transactional.





Delete files already migrated

Reads back a past copy run's audit trail (reports/.copies/) so the files it successfully copied can be removed from the source provider. Only delete once you've confirmed the app's own database references have actually been repointed at the new provider — this list is not re-verified against the database, it only reflects what the copy step wrote to the destination at the time.
