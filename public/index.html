Auto reconciliation

Enter a database name and it discovers file-reference columns from the schema itself (information_schema) instead of typing table/column mappings by hand. Best-effort: review the discovered columns in the downloaded report before trusting it fully. Every TEXT/JSON column is also scanned for embedded Object Storage URLs (e.g. CKEditor/CKFinder uploads referenced only inside rich content) — anything found there is moved out of Orphan into Protected, so Orphan stays a safer basis for anything you plan to delete outside this tool.




DO cleanup candidates

Same auto-discovery as above, plus a scan of every TEXT/LONGTEXT column for Object Storage URLs embedded inline (e.g. CKEditor/CKFinder uploads referenced only inside HTML content). Produces an .xlsx listing which orphaned objects are safe cleanup candidates vs. which are protected because they're still referenced from inside rich-text content. Read-only — nothing is deleted.




Reconciliation

Match Object Storage against hand-typed MySQL table/column file references. Database is optional — when given, every TEXT/JSON column in it is also scanned for embedded Object Storage URLs, so Orphan doesn't wrongly include a file still referenced only inside rich-text/CKEditor content.

Copy files to another provider

Upload a reconciliation report you already downloaded — this reads its "Matched" sheet back in (files already confirmed to exist in both the database and storage) and copies every one of them to another provider (e.g. DigitalOcean -> Wasabi, ahead of a migration), no review list in between. Nothing is deleted from the source here — update the app's own database references to the new provider separately once you've confirmed the copy worked. Safe to re-run with the same (or an overlapping) report: anything already present at the destination is skipped instead of re-copied, unless "overwrite" below is checked. The destination bucket is created automatically if it doesn't exist yet, and copied files default to publicly readable (a plain object copy doesn't carry the source's ACL over, so without this a file that used to be public silently becomes private and every link to it breaks). Source and destination provider can also be the same (e.g. moving between two buckets on the same account) — a destination bucket is then required, and it must differ from every source bucket. Produces a downloadable .xlsx report with every file's new destination link.





Restore files from archive

Paste one or more archive URLs (or bare "<archive bucket>/<original bucket>/<original key>" paths), one per line — e.g. https://sgp1.digitaloceanspaces.com/scola-school-archives/scola-rosetta/s3_ckf_files/files/foo.mp3 restores to https://sgp1.digitaloceanspaces.com/scola-rosetta/s3_ckf_files/files/foo.mp3 (the archive bucket segment is dropped; everything after it becomes the destination bucket + key). Same non-destructive behavior as "Copy files to another provider" above — nothing is deleted from the archive, and re-running with overlapping lines skips anything already at the destination unless "overwrite" is checked. Produces a downloadable .xlsx report.



Trim the report down to just the rows you want first if you don't want everything in it restored. If a file is selected, it's used instead of the pasted lines above.


Update database URLs after migration

Upload the completed storage migration report. Only Copied/Skipped rows with Table, Column, and Row ID are eligible. Each database value must still exactly match Source Path before it is changed to Destination URL; changed rows are reported as conflicts and left untouched. Each row commits on its own, so if a large run gets cut off partway, use "Retry — continue remaining" to resume without reapplying already-updated rows.





Delete files already migrated

Upload a completed storage migration report. Only rows marked Copied or Skipped are included; Failed rows are excluded automatically. Select the source provider carefully, and only delete after confirming the database URLs have been updated. The summary is shown before all eligible source objects are deleted. This does not re-verify the database or destination storage.




Delete previously excluded files

Upload a deletion report this app generated earlier. Reads its Excluded sheet and re-checks each destination link — many exclusions there are transient (a connection timeout while checking the link, not the file being genuinely unsafe) and can turn out fine on a retry. Rows still excluded (permanently invalid, or missing bucket/key/URL entirely) stay excluded.




Delete files from report

Upload an Orphan or Cleanup Candidates report you already downloaded and reviewed. Every row in the file is processed — there's no per-row selection step. Nothing happens until you type the confirmation phrase. Each file is first archived to the scola-school-archives bucket (under a folder named after its original bucket), with private presigned download links. Source files are deleted only after the signed archive download matches the complete source contents. Failed checks retain the source. The resulting report contains archive links and copy failures.
