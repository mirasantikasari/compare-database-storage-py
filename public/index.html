Auto reconciliation

Enter a database name and it discovers file-reference columns from the schema itself (information_schema) instead of typing table/column mappings by hand. Best-effort: review the discovered columns in the downloaded report before trusting it fully. Every TEXT/JSON column is also scanned for embedded Object Storage URLs (e.g. CKEditor/CKFinder uploads referenced only inside rich content) — anything found there is moved out of Orphan into Protected, so Orphan stays a safer basis for anything you plan to delete outside this tool.




DO cleanup candidates

Same auto-discovery as above, plus a scan of every TEXT/LONGTEXT column for Object Storage URLs embedded inline (e.g. CKEditor/CKFinder uploads referenced only inside HTML content). Produces an .xlsx listing which orphaned objects are safe cleanup candidates vs. which are protected because they're still referenced from inside rich-text content. Read-only — nothing is deleted.




Reconciliation

Match Object Storage against hand-typed MySQL table/column file references. Database is optional — when given, every TEXT/JSON column in it is also scanned for embedded Object Storage URLs, so Orphan doesn't wrongly include a file still referenced only inside rich-text/CKEditor content.
